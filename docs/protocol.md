# 展示端协议

本文是所有展示方式共用的契约。采集端（`core/`）汇总出一份状态快照，通过两种方式交给展示端：

- **设备类展示端**（如 AI Passport）：经 USB 串口或蓝牙接收 AR1 行协议；
- **本机展示端**（以后的电脑浮窗等）：读取 `~/.agent-run/run/status.json`。

## 1. 状态快照

| 字段 | 含义 |
|---|---|
| `cc` / `cx` / `ds` | Claude Code、Codex、dsh 正在执行任务的会话数 |
| `done` | 今日（本地时区）完成的轮数 |
| `wn` | 等你处理的会话总数 |
| `waiting` | 按进入等待的先后排序的列表，每项为 `[工具, 原因]`；工具为 `claude`、`codex`、`dsh`，原因为 `A`（等待授权）或 `Q`（等你回答） |

设备类展示端另外从状态帧收到主机的本地时间（当日分钟数），用于夜间勿扰，见 §2.1 的 `tm` 字段。

快照只包含计数、工具代号和原因代号，不包含项目名、路径、提示词或会话标题。

此外，采集端按工具给出专用页面的数据（目前为 Claude Code 与 Codex）：等你处理、后台运行、今日完成三项计数，5 小时、每周两个订阅限额窗口的已用百分比与重置时间，以及订阅类型的显示名（如 `Max 5x`、`Pro Lite`）。来源与取值规则见 [专用页面方案](specs/2026-11-09-agent-run-agent-pages-design.md) §3、§9。

## 2. AR1 行协议

每条消息一行 ASCII，以 `\n` 结束（`\r` 也视为行尾），单行不超过 160 字节。

### 2.1 主机 → 展示端

**状态帧**：状态变化时立刻发送，之后定期重发作为心跳。

```
AR1 S seq=<0-65535> cc=<0-99> cx=<0-99> ds=<0-99> done=<0-999> wn=<0-99> w=<列表> [tm=<0-1439>]
```

- `w`：最多 3 项，格式为 `CC:A,CX:Q`（工具代号 `CC`、`CX`、`DS`，原因 `A`、`Q`）；没有等待项时为 `-`。`wn` 可以大于列表项数。
- `tm`：可选，主机本地时间的当日分钟数（`时 × 60 + 分`）。主机每次发送状态帧（含心跳）都带上，取不到本地时间时省略。展示端据此判断夜间勿扰（22:00–08:00），没收到时按时间未知处理；出现但超出范围时整帧丢弃。见 [屏幕方案](specs/2026-11-10-agent-run-screen-dnd-design.md) §8。
- 示例：`AR1 S seq=17 cc=3 cx=1 ds=1 done=21 wn=2 w=CC:A,CX:Q tm=1342`

**工具帧**：每个工具一行，内容变化时发送；连上展示端、展示端重新发出 `HELLO` 时，每个工具各发一帧。不随心跳重发。

```
AR1 A t=<CC|CX> wn=<0-99> bg=<0-99> done=<0-999> h=<用量> hr=<分钟> w=<用量> wr=<分钟> [p=<套餐>]
```

- `wn`、`bg`、`done`：该工具等你处理、后台运行、今日完成的数量。工作中的数量沿用状态帧的 `cc`、`cx`。
- `h`、`w`：5 小时、每周窗口的已用百分比 `0-100`；`-` 表示暂无数据，`x` 表示账户没有这一窗口。
- `hr`、`wr`：距重置的分钟数 `0-20160`，未知时为 `-`。展示端不需要时钟。窗口的重置时间已过时，主机发送 `0` 与 `-`。
- `p`：可选，订阅类型的显示名，1–10 个字母、数字或下划线，下划线表示空格（`Pro_Lite` 显示为 “Pro Lite”）。套餐未知时整个字段省略；出现时不合法，展示端整帧丢弃。
- 示例：`AR1 A t=CX wn=0 bg=0 done=3 h=x hr=- w=5 wr=6110 p=Pro_Lite`
- 不认识工具帧的展示端按兼容规则忽略它；展示端没有收到某个工具的工具帧时，按暂无数据显示。

**握手**：`AR1 PING`

### 2.2 展示端 → 主机

`AR1 HELLO fw=<固件版本> proto=1`：开机时主动发送一次，收到 `PING` 时回复。状态帧不需要确认。

### 2.3 兼容规则

- 展示端忽略未知键，也忽略不以 `AR1 ` 开头的行（例如设备日志）。
- 字段缺失、超出范围或超长的帧整帧丢弃。
- 主机忽略展示端输出的日志行。

### 2.4 心跳与超时

| 链路 | 主机心跳 | 展示端判定离线 |
|---|---|---|
| USB 串口 | 2 秒 | 10 秒没有合法状态帧 |
| 蓝牙 | 5 秒 | 15 秒没有合法状态帧 |

## 3. 传输层

### 3.1 USB 串口

- ESP32-C3 原生 USB Serial/JTAG，macOS 上显示为 `/dev/cu.usbmodem*`，USB 厂商号 `0x303A`。
- 主机以 `O_NOCTTY | O_NONBLOCK` 打开，清除 `HUPCL`，不主动翻转 DTR/RTS，避免让设备复位。

### 3.2 蓝牙（BLE）

- 设备是外设，广播名为 `AgentRun-XXXX`（蓝牙 MAC 地址末两字节）。
- GATT 服务沿用 Nordic UART 的 UUID：
  - 服务：`6e400001-b5a3-f393-e0a9-e50e24dcca9e`
  - RX `6e400002-…`：主机写入 AR1 字节流，可以分片写入，要求链路已加密；
  - TX `6e400003-…`：设备用通知回复 HELLO。
- 安全：LE Secure Connections 的 Just Works 配对并绑定。第一次配对要在设备上按 OK 确认，确认前收到的数据会被丢弃；已有绑定时，其他主机的配对一律拒绝。
- macOS 上由 `transports/macos-ble/` 的桥接程序负责蓝牙收发。它与采集端的交互：
  - 采集端把状态行写到 `~/.agent-run/run/ble.sock`（Unix 数据报）；
  - 桥接程序每 2 秒写一次 `~/.agent-run/run/ble-status.json`：`{"connected", "name", "fw", "updated", "hint"}`；
  - `connected` 只在设备回过 HELLO 后为 `true`。

## 4. 截屏（设备类展示端可选）

与 AI Passport 社区的 `FAP_SCREENSHOT_V1` 协议一致，只在 USB 串口上使用：

1. 主机发送一行 `FAP_SCREENSHOT_V1`；
2. 设备回一行 `FAP_SCREENSHOT_V1 <宽> <高> RGB565LE <字节数>`；
3. 设备紧接着发送恰好 `<字节数>` 字节的小端 RGB565 像素，按行从上到下排列。

传输期间设备不输出日志，主机按声明的字节数精确读取。

## 5. 本机状态文件

`~/.agent-run/run/status.json` 在内容变化时和每 5 秒刷新一次。除第 1 节的快照字段外，还包含：

| 字段 | 含义 |
|---|---|
| `link` / `link_type` / `port` | 当前设备链路：是否连接、`usb` 或 `ble`、端口或设备名 |
| `demo` | 是否处于演示模式 |
| `recent` | 最近 20 条事件，只含时间、工具、事件名、工具名、通知类型，供排查使用 |
| `agents` | 按工具（`claude`、`codex`）的专用页面数据：`wn`、`bg`、`done`；`five_hour`、`seven_day` 各为 `{"used": 已用百分比, "resets_at": Unix 秒或 null}`、`"none"`（无此限额）或 `null`（暂无数据）；`usage_updated` 为用量的数据时间，`usage_error` 为最近一次未能更新的原因；`plan` 为订阅类型的显示名（未截断），未知时为 `null` |
| `updated` | 写入时间戳；超过 10 秒没更新，说明采集端没有在运行 |

事件到会话状态的映射规则见 [v1 设计方案](specs/2026-11-08-agent-run-design.md) §5。
