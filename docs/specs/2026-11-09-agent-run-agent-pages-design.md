# Agent Run! 工具专用页面设计方案（v1.2：Claude Code、Codex 用量与任务）

- 日期：2026-11-09
- 状态：已实现、2026-11-09 暂停待真机验证；数据来源最终决定见 §8.3，暂停时的待验证项见 §8.5
- 前置：[v1 设计方案](2026-11-08-agent-run-design.md)、[无线方案](2026-11-08-agent-run-wireless-design.md)

## 1. 目标

1. Claude Code、Codex 各有一个专用页面，显示该工具的 5 小时用量、每周用量（百分比与距重置时间），以及任务信息：工作中、等你处理、后台运行、今日完成。
2. 首页、Claude Code、Codex 三页用上下键循环切换，可以切回首页。
3. 在专用页面上出现“等你处理”时照常跳到提醒画面；等你处理清空后回到刚才所在的页面。
4. 页面结构留出扩展位，以后加 dsh 等工具只需增加一项工具代号和一页。
5. 界面沿用现有风格：深色底、圆角卡片、黄色强调色、橙色警示色、5×7 像素数字与 14 px 中文标签。

## 2. 非目标

- dsh 页面：dsh 没有公开的用量限额数据，本期不做，只保留扩展位。
- 用量历史曲线、按模型拆分的用量（如 Opus 单独的周限额）、费用估算。
- 在设备上切换账号或查看会话详情。
- 云端会话（Claude Code on the web、Codex 云任务）的任务数：采集端只能收到本机 hook 事件，与 v1 相同。

## 3. 用量数据来源（已选定方案 A）

### 3.1 已核实的事实（2026-11-09，本机）

| 来源 | 内容 | 覆盖范围 | 性质 |
|---|---|---|---|
| Claude Code 状态栏输入 `rate_limits` | `five_hour`、`seven_day` 各有 `used_percentage`（0–100）与 `resets_at`（Unix 秒）；只对 Pro、Max 等订阅用户、且在会话第一次 API 响应之后出现 | 只在运行 statusLine 的会话里：本机实测桌面端 Code 页会话不调用 statusLine（项目级配置 2 秒刷新，约 5 分钟内零次调用） | 官方文档字段 |
| Claude Code hook 载荷 | 没有用量字段（只有 `quota_auto_resume_*` 通知类型，不带数值） | — | 官方文档 |
| Claude 订阅用量接口 `GET https://api.anthropic.com/api/oauth/usage` | Claude Code 的 `/usage` 使用的接口，返回 `five_hour`、`seven_day` 等窗口的用量与重置时间；鉴权用 Claude Code 存在钥匙串 `Claude Code-credentials` 里的 OAuth 访问令牌 | 与会话运行方式无关：桌面端、CLI、IDE 扩展都覆盖 | 非公开接口；字段名以实现时实测为准 |
| Codex 会话文件 `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` | 每轮的 `event_msg` / `token_count` 事件带 `rate_limits`：`primary`、`secondary` 各有 `used_percent`、`window_minutes`、`resets_at`（Unix 秒），另有 `plan_type`、`limit_id`（本机只见到 `codex`） | CLI 与桌面端都写这些文件 | 非公开格式，读本机文件 |
| 钥匙串条目 `Claude Code-credentials`（实现时补查） | `claudeAiOauth` 下有 `accessToken`、`refreshToken`、`expiresAt`（Unix 毫秒）等；本机此时 `accessToken` 为空串、`expiresAt` 为 0、没有 `refreshToken`，CLI 的刷新令牌已于 11-04 过期。桌面端会话的鉴权由宿主提供（会话环境里有 `CLAUDE_CODE_SDK_HAS_HOST_AUTH_REFRESH`），不经过这个条目 | 只有登录过的 Claude Code CLI 会写入可用令牌 | 本机实测 |

两个容易踩的点：

- Codex 的 `primary` / `secondary` 不固定对应 5 小时与每周。本机账户（`plan_type` 为 `prolite`）只有一个窗口：`primary.window_minutes = 10080`（每周），`secondary` 为 `null`，没有 5 小时窗口。必须按 `window_minutes` 归类：300 为 5 小时，10080 为每周。
- 本机 Codex 会话文件共 6 个、合计 243 MB，单个文件很大。只读最近修改的几个文件的末尾，不整文件解析。

### 3.2 Claude Code 用量的三个方案

| 方案 | 做法 | 优点 | 代价与风险 |
|---|---|---|---|
| **A. 订阅用量接口（推荐）** | 守护进程用 `security` 从钥匙串读出 Claude Code 的访问令牌，每 5 分钟、以及每次 Claude Code 一轮结束后（两次至少间隔 60 秒）请求一次用量接口 | 桌面端、CLI、IDE 扩展都有数据，刷新及时；不改 Claude Code 配置 | ① 非公开接口，可能改名、改字段或限流，失效时页面显示“暂无数据”；② 守护进程要读登录凭据，首次读取时 macOS 会弹窗，需点“始终允许”；③ 用 Claude Code 的登录令牌访问非公开接口，是否符合服务条款没有明确说法，存在被限制的可能；④ 令牌过期（Claude Code 一段时间没运行）时不自行刷新，暂停更新，等 Claude Code 下次运行刷新令牌 |
| B. 状态栏中继 | `install-hooks` 同时写入 statusLine：一个小脚本把 `rate_limits` 转发给守护进程（已有自定义状态栏时串接原命令，输出原样返回） | 官方文档字段，不碰凭据，不联网 | 只有 CLI 交互会话会更新：主要用桌面端时，数据会一直停在上次用 CLI 的时刻；要改动用户的状态栏配置 |
| C. 不显示 Claude Code 用量 | 页面只显示任务信息，用量一栏写“暂无数据” | 零风险 | 达不到需求 |

**推荐 A。** 理由：从本机情况看，你主要在桌面端使用 Claude Code，B 在这种用法下基本拿不到数据。A 的风险集中在“非公开接口”和“读凭据”两点，实现上按 §5.3 收紧：令牌只在内存里用于这一次请求，不写盘、不进日志、不发给设备；只发 GET 请求；绝不刷新令牌（刷新会轮换 refresh token，可能让 Claude Code 掉登录）。如果你不接受读取登录凭据，选 B。

### 3.3 Codex 用量

读会话文件（唯一不需要凭据的来源）：每 30 秒找出最近 7 天内修改过的会话文件，按修改时间取最新的 3 个，各读末尾 512 KB，取时间最晚的一条带 `rate_limits` 的 `token_count` 事件，按 `window_minutes` 归类。

被否：用 `codex app-server` 的 `account/rateLimits/read`。它是 Codex 对外的协议，但要常驻或定时拉起一个 Codex 进程，占用与复杂度都高于读文件；会话文件格式变化导致读不到时，再改用它。

### 3.4 重置与过期

- 某个窗口的 `resets_at` 已过：用量按 0% 处理，重置时间显示“未知”。Codex 只在每轮对话时写入用量，重置后没有新事件说明这段时间没用过，0% 是准确的。
- 读到了用量记录但其中没有某个窗口（如本机 Codex 没有 5 小时窗口）：显示“无此限额”，与“暂无数据”区分。

## 4. 设备端

### 4.1 页面与按键

| 状态 | 上键 | 下键 | 确定单击 |
|---|---|---|---|
| 首页 | 切到 Codex 页 | 切到 Claude Code 页 | 打开设置菜单（不变） |
| Claude Code 页 | 切回首页 | 切到 Codex 页 | 打开设置菜单 |
| Codex 页 | 切到 Claude Code 页 | 切回首页 | 打开设置菜单 |
| 等你处理、未连接、配对确认 | 不起作用 | 不起作用 | 设置菜单（配对确认时为接受） |

- 页面顺序为首页 → Claude Code → Codex → 首页，下键前进、上键后退，循环。
- **画面优先级：** 配对确认 > 设置菜单 > 未连接 > 等你处理 > 用户所在的页面。等你处理清空、重新连上、关闭菜单后，都回到用户所在的页面。
- 所在页面在熄屏、亮屏后保持；重启（含深睡唤醒）后回首页。没有自动回首页的超时。
- 熄屏时按键只亮屏，不切页（沿用第 1–3 项实现的 `ar_keywake`）。
- 专用页面不播放宠物动画；跑速、完成提示音与亮屏规则与首页相同。在专用页面上有会话完成时，“今日完成”格用强调色显示约 5 秒，相当于首页的“完成 +N”。

### 4.2 专用页面布局（240×320，与首页同一套边距）

```
y=15   AGENT RUN!                     [音量][链路] 85% [电池]   标题栏不变
y=38   Claude Code                                  ○ ● ○       工具名（14 px 中文字体）+ 页码点
y=60   ┌──────────────────────────────────────────┐
       │ 5 小时用量                          23%  │            卡片 204×64，底色同计数格
       │ ████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ │            进度条 180×8，≥80% 改用橙色
       │ 2 小时 15 分后重置                       │
       └──────────────────────────────────────────┘
y=132  ┌ 每周用量                            41%  ┐            同上
       │ ████████████████░░░░░░░░░░░░░░░░░░░░░░░ │

       └──────────────────────────────────────────┘

       └──────┘ └──────┘ └──────┘
```

- 百分比用 3 倍像素字，右对齐在卡片标题行；“暂无数据”“无此限额”时百分比位置显示 `--`，进度条留空，第三行写原因。
- 距重置时间：不足 1 小时写“N 分钟后重置”，不足 1 天写“N 小时 M 分后重置”，否则写“N 天 M 小时后重置”。
- 页码点：三个 6×6 圆点，所在页为强调色，其余为轨道色。
- 首页底栏右侧的“等你 N”保持不变；首页不加页码点，避免挤占计数区。

### 4.3 资源

- 两个卡片的百分比画在首页大数字缓冲（80×42）的上下两半里，各 80×21；专用页面显示时首页大数字隐藏，回到首页时重画。三格计数复用首页的计数格对象与缓冲，另加三个中文标签。没有新增像素缓冲。
- 新增 LVGL 对象约 25 个。实测全部画面创建后 LVGL 内存池峰值 22.2 KB，原来的 24 KB 扣除分配器开销后放不下（开机即在 `LV_ASSERT_MALLOC` 处死循环，被任务看门狗卡住），改为 32 KB。池子变大后开机空闲堆的最大连续块约 28 KB，截屏原来 30 KB 的条带申请不到，条带改为 40 行（19.2 KB）。`main.c` 在编译期拦下小于 32 KB 的配置，因为已有的 `sdkconfig` 不会自动采用 `sdkconfig.defaults` 的新值。实测数据见 §8。
- 新增中文字符（小时、用量、每周、分钟、重置、天、暂无数据、无此限额、后台运行、上下键切换等）后，用 `tools/gen_agent_run_font.sh` 重新生成字体子集。

## 5. 采集端

### 5.1 新增的数据

- **按工具的任务数：** 在 `Aggregator` 上新增按工具的等你处理数、后台运行数、今日完成数。今日完成按工具分别计数，`state.json` 增加 `done_by_tool`，旧文件没有这个键时按 0 处理，总数仍用 `done`。
- **用量：** 新模块 `core/agent_run/usage.py`，对每个工具给出 5 小时、每周两个窗口，每个窗口为“已用百分比 + 重置时间”“无此限额”或“暂无数据”三者之一。

### 5.2 协议（AR1 新增一种帧，向后兼容）

主机 → 展示端，每个工具一行：

```
AR1 A t=<CC|CX> wn=<0-99> bg=<0-99> done=<0-999> h=<用量> hr=<分钟> w=<用量> wr=<分钟>
```

- `wn`、`bg`、`done`：该工具等你处理、后台运行、今日完成的数量。“工作中”沿用状态帧的 `cc`、`cx`，不重复发送。
- `h`、`w`：5 小时、每周窗口的已用百分比 `0-100`；`-` 表示暂无数据，`x` 表示无此限额。
- `hr`、`wr`：距重置的分钟数，`0-20160`；未知时为 `-`。设备没有时钟，倒计时由主机换算后发送。
- 示例：`AR1 A t=CX wn=0 bg=0 done=3 h=x hr=- w=5 wr=6110`
- 发送时机：内容变化时立即发送（距重置的分钟数每分钟变化一次，所以至少每分钟一帧），连上设备或设备重新上线时把每个工具各发一帧。不随 2 秒心跳重发。
- 兼容：旧固件忽略不认识的 `AR1 A` 行；新固件没收到 `A` 帧时，专用页面显示“暂无数据”。蓝牙桥接只检查 `AR1 ` 前缀与长度，不需要改。`HELLO` 仍为 `proto=1`，固件版本升到 `0.4.0`。
- 隐私：只含计数、百分比和分钟数，不含账号、套餐、令牌、项目或会话内容。`plan_type` 不上设备。

### 5.3 Claude Code 用量接口的约束（选 A 时）

- 令牌读取：`security find-generic-password -s "Claude Code-credentials" -w`，解析出访问令牌与过期时间；为空或已过期就跳过本次，不刷新。
- 请求头：`Authorization: Bearer <令牌>`、`anthropic-beta: oauth-2025-04-20`、`User-Agent: agent-run/<版本>`。响应按 `five_hour`、`seven_day` 各自的 `utilization`（0–100）与 `resets_at`（ISO 8601）解析；窗口为 `null` 记为无此限额。**这组字段名尚未实测**（本机没有可用令牌，见 §8），登录 CLI 后按 P3 核对。
- 请求：只发 GET，10 秒超时，在后台线程里执行，不阻塞守护进程主循环。
- 限流：正常每 5 分钟一次；Claude Code 一轮结束后提前刷新，但两次请求至少间隔 60 秒；收到 401 等到令牌变化再试，收到 429 或网络错误按 5、10、20 分钟退避。
- 令牌只在内存里用于本次请求：不写盘、不进日志、不进 `status.json`、不发给设备。日志只记录状态码与“已更新 / 失败原因”。
- `agent-run status` 显示每个工具的用量、数据时间与最近一次失败原因，便于排查。

### 5.4 本机状态文件

`status.json` 新增 `agents`，每个工具一项：`wn`、`bg`、`done`、`five_hour`、`seven_day`（各为 `{"used": 23.5, "resets_at": 1794632374}`、`"none"` 或 `null`）以及 `usage_updated`。本机展示端可以直接使用。

### 5.5 演示模式

`agent-run demo` 同时发送两个工具的示例 `A` 帧（含一个 ≥80% 的窗口和一个“无此限额”的窗口），演示期间可以用上下键查看专用页面。

## 7. 被否方案

| 方案 | 否决原因 |
|---|---|
| 把用量塞进现有状态帧 `S` | `S` 帧随 2 秒心跳重发，用量变化很慢；按工具展开后单行接近 160 字节上限，再加工具会超长 |
| 设备按 Unix 时间自己倒计时 | 设备没有实时时钟，需要额外同步时间；主机直接发剩余分钟更简单 |
| 用量一栏按本地会话记录估算（统计 token） | 订阅限额的额度不公开，估算出的百分比没有依据 |
| 等你处理时也允许上下键切页 | 用户要求提醒优先；需要查看专用页面时先处理提醒 |
| 专用页面一段时间无操作自动回首页 | 用户只要求能切回首页；停留在专用页面也是一种常驻视图 |

## 8. 实现记录与验收（2026-11-09）

### 8.1 真机实测数据

设备：AI Passport，经 USB 连接；调试固件额外每 2 秒打印栈余量与内存，验证后已刷回正式固件。

| 项目 | 结果 |
|---|---|
| LVGL 内存池（32 KB） | 峰值已用 22,232 B，空闲 7,888 B |
| 主任务栈（7,168 B） | 连续截屏 21 次后最低余量 2,416 B |
| 空闲堆 | 开机后约 40.9 KB；截屏期间最低 17,040 B（条带 19.2 KB 占用期间） |

### 8.2 验收结果

| 编号 | 结果 |
|---|---|

### 8.3 数据来源的最终决定（2026-11-09）

Claude Code 用量**定为方案 A：读 CLI 的 OAuth 令牌**（`Claude Code-credentials`），不加桌面端来源。理由如下，均为本机实测：

- **合规性分级：** 订阅（本机为 Pro）的「5 小时 / 每周」限额**没有官方公开 API**。唯一官方文档化的程序化来源是 Claude Code 状态栏输入里的 `rate_limits`，但它只在 CLI 交互会话里有，桌面端不触发。`/usage` 用的 `api/oauth/usage` 是非公开接口，用自己的令牌读自己的数据功能上可行，但无文档、不受支持，合规性无明确说法——这是方案 A 的既有风险，保持不变。API 付费账户另有官方的 Usage & Cost Admin API，但它查 API 组织消耗，不覆盖订阅限额，不适用。
- **桌面端令牌为何不采用：** 桌面端的 OAuth 令牌加密存在 `~/Library/Application Support/Claude/config.json` 的 `oauth:tokenCacheV2`（按「账号+组织+scope」为键，带 `sessions:claude_code` scope 的那条对应 Claude Code 会话）。它用 `Claude Safe Storage` 钥匙串密钥按 Chromium 的 `v10`/AES-128-CBC 方案加密；本机用 openssl 实测能解出可用令牌。**但不采用：**(1) `Claude Safe Storage` 是桌面端全部本地加密数据的主密钥，任何非桌面端程序读取它，macOS 每次都弹授权框，点「始终允许」才不再弹——等于把主密钥永久交给采集程序，授权范围远超单个用量令牌；(2) `v10` 解密格式无文档，桌面端更新即可能失效；(3) 解密需额外实现（系统 Python 3.9 无 `cryptography`，要靠 openssl 外部进程）。综合安全与脆弱性，不值得。

**结论：** 只用桌面端的用户，在终端运行一次 `claude` 登录即可让专用页面有数据；未登录时显示「暂无数据」，`agent-run status` 写明原因。方案 B（状态栏中继）同样只在 CLI 会话里有数据，不解决桌面端，未采用。
